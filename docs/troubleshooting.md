# Troubleshooting

Use these checks for the pinned Cosmic deployment. Keep private environment files and code plaintext out of issue reports. Supply versions, safe error codes and the failing step instead.

| Symptom                                            | Check and expected result                                                                                     | Correction                                                                                                                                                         |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Administration is missing                          | `python3 tools/cosmic.py --directory ../CosmicCardServer admin list` includes the signed-in native account ID | Grant that ordinary account locally, then refresh. GM level is unrelated. The test collector is not promoted.                                                      |
| A banned or deleted account retains a listed grant | List reports its immutable account ID and unavailable status                                                  | Use `admin revoke --account-id ID` to remove the stale grant. Revoke can recover access control without a live native identity.                                    |
| Login or wallets are unavailable                   | Run managed `doctor`; game, callback, lease and storage must pass                                             | Inspect scoped game/card service logs. Browsing remains available; Retry retains purchase intent. An outage does not mean the account was signed out.              |
| A checkout total is unavailable                    | Check the selected balance at the top and in the purchase dialog                                              | Fund or select that exact native cash type. Balances do not combine or fall back.                                                                                  |
| An old purchase is pending                         | Find its durable order ID in Administration → Orders & activity                                                 | Restore game/storage readiness and retry that order. Retain its request key; do not create a replacement purchase or manually credit cash.                         |
| Preview reports a conflict                         | Check the active catalog version and policy revision                                                          | Export or reload the active catalog, reconcile the draft, then preview again. Another administrator may have published first.                                      |
| A restarted site ignores edits to the seed JSON    | Export the active catalog through Administration                                                              | `CATALOG_PATH` seeds empty state only. Load the file into an admin draft, preview and publish.                                                                     |
| Import is too large                                | Catalog preview permits 2 MiB; ordinary requests permit 16 KiB                                                | Use the documented five-set catalog or split authoring changes. Ensure every reverse proxy allows 2 MiB only for the preview route.                                |
| A card image is missing                            | Verify supported image path, file permissions and `ASSET_ROOT`                                                | Place an owned image below that root. Do not use traversal, query strings or unsupported remote sources. External scans can disappear; symbols provide a fallback. |
| A POST returns FORBIDDEN                           | Exact Origin and current session CSRF must agree                                                              | Correct `PUBLIC_ORIGIN`, proxy host forwarding and TLS; reload the form. Do not weaken Origin checking.                                                            |
| A reward is preparing                              | Rewards → registration status shows its attempts/error                                                        | Restore the game connection and retry registration. Never paste code plaintext into logs. The owning player can reveal it once registered.                         |
| A reward does not become USED                      | Game inventory save and the signed receipt must agree                                                         | Check callback readiness, outbox retry diagnostics and game persistence. Do not manually set USED or issue a replacement reward.                                   |
| The game exits after database or lease loss        | The service supervisor restarts the same single enabled game writer                                           | Restore MySQL, then verify doctor and login. Do not run another enabled game process against the same database.                                                    |
| Restore refuses an archive or destination          | Checksums, installation identity and empty-target rules must pass                                             | Preserve the archive. Use the documented recovery command and exact original project ID; never disable validation.                                                 |

For managed logs, use `docker compose -f ../CosmicCardServer/compose.json logs --tail 100 cards cosmic`. Manual installs use `journalctl -u card-library.service -n 100 --no-pager` and the existing Cosmic unit's logs.

See [administration](administration.md) for role recovery and draft workflows, [operations](operations.md) for consistent backups and disaster recovery, and [protocol](protocol.md) for endpoint limits and error behavior.
